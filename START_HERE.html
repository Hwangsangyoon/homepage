01 · 프로젝트를 다시 만들지 않습니다

v6가 운영되는 동일한 Netlify 프로젝트를 사용합니다.

현재 홈페이지가 homepage라는 프로젝트에 있다면 그 프로젝트에 v7을 배포합니다. 주소가 smart-samsung.netlify.app이라면 주소는 그대로 유지됩니다. 홈페이지 프로그램 버전만 7.0.0으로 변경됩니다. 프로젝트 이름이나 주소만 보고 판단하지 말고 Project ID를 비교하세요.

새 Netlify 프로젝트를 만들거나 기존 프로젝트를 삭제하면 안 됩니다.
기존 v6의 저장소 optic-v6-data, optic-v6-media 이름을 그대로 사용합니다. v7이라고 저장소 이름을 바꾸면 기존 자료가 보이지 않습니다. Supabase 자료는 자동으로 가져오지 않으며, 기존 Supabase도 백업 전에 삭제하지 마세요.

가능하면 먼저 v6 관리자 → 백업·가져오기에서 JSON을 내려받고 매장·행사 원본사진을 별도 보관합니다. 기존 로그인이 안 되어 백업을 못 했다면 자료를 삭제하거나 초기화하지 말고, 같은 프로젝트에 업데이트한 뒤 v7에서 백업하세요. 자동으로 초기 데이터를 덮어쓰지 않도록 구성했습니다.

유지되는 것바뀌는 것
v3 기반 디자인, 사진, 공지, 제품·재고·고객·상담 자료, 같은 프로젝트 주소관리자 로그인: 1111/설정코드 → 이메일 6자리 인증번호
Netlify Blobs 저장소 이름과 기존 자료 ID신청 버튼 처리시간 제한, 중복저장 방지, 삭제·복원 및 일일 백업

Supabase 프로젝트 생성, SQL, RLS, 복구 링크/Redirect URL 설정은 이번 버전에 필요하지 않습니다. Netlify와 이메일 발송서비스만 사용합니다.

02 · 처음 한 번만 설정

관리자 이메일과 인증메일 발송 키 2개를 등록합니다.

이메일 인증번호는 인터넷 메일서비스가 실제로 발송해야 합니다. Netlify는 홈페이지·서버·자료를 담당하고, Resend는 인증번호 메일을 담당합니다. 별도의 데이터베이스 가입은 없습니다. 이메일 서비스 계정·발신 설정은 생략할 수 없습니다.

A. 우선 대표님 본인 이메일로 시험하기

  1. Resend에서 관리자 로그인에 사용할 것과 같은 이메일 주소로 가입합니다. 예: 대표님이 실제 소유한 Gmail.
  2. Resend의 API Keys → Create API Key에서 메일 발송 권한(Sending access)을 가진 키를 만듭니다. 키는 보통 re_로 시작합니다. 복사한 키를 안전하게 보관하고 채팅·GitHub에는 올리지 않습니다.
  3. Netlify에서 현재 v6 프로젝트 → Project configuration → Environment variables → Add a variable을 엽니다.
  4. 아래 두 값을 저장합니다. Functions 범위 포함, Production에 값 적용. 처음 시험에는 All scopes / Same value for all deploy contexts도 가능합니다.
Key (그대로 복사)Value비밀값

발신자 설정을 생략하면 onboarding@resend.dev가 사용됩니다. 이 주소는 Resend 가입 이메일 본인에게 보내는 시험용입니다. 가입 이메일과 다른 주소로는 발송되지 않을 수 있습니다. 실제 운영은 아래 B의 도메인 인증을 완료하세요. 홈페이지가 메일 키를 발급하거나 Gmail 비밀번호를 요구하지 않습니다.

B. 운영용 발신자 설정 (도메인 인증)

  1. Resend → Domains → Add domain에서 소유 도메인의 인증용 하위도메인(예: auth.smartsamsunggopt.co.kr)을 등록합니다. 이 예시는 DNS가 이미 설정되었다는 뜻이 아닙니다.
  2. Resend가 보여주는 TXT/DKIM/SPF/MX 등 DNS 레코드의 이름·종류·값을 그대로 실제 네임서버 업체(Hosting.kr 등)에 추가합니다. 기존 메일 MX/TXT는 삭제하지 마세요. 수신 메일을 운영할 필요는 없고 발송 도메인 인증을 수행합니다.
  3. Resend에서 Verified 상태를 확인합니다. API 키를 특정 도메인으로 제한했다면 인증한 도메인과 일치시킵니다.
  4. Netlify 환경변수 OPTIC_FROM_EMAIL에 실제 인증한 주소를 등록합니다.
Key: OPTIC_FROM_EMAIL
Value 예시: Smart Optic <login@auth.smartsamsunggopt.co.kr>

환경변수를 저장한 뒤에는 새 배포가 필요합니다. 1111, OPTIC_SETUP_KEY, Supabase 키, 복구메일 이동주소는 v7 관리자 로그인에 사용하지 않습니다. 옛 환경변수는 다른 프로젝트에서 쓰고 있는지 확인한 후 정리하세요.

03 · 같은 GitHub 저장소, 같은 Netlify 프로젝트

파일 업데이트로 프로그램만 교체합니다.

A. GitHub가 이미 연결된 경우

  1. v7 ZIP을 새 폴더에 압축 해제합니다. 이전 v6 폴더를 보관합니다.
  2. 현재 Netlify에 연결된 동일한 GitHub 저장소/배포 브랜치에 v7 파일을 반영합니다. 바깥 폴더를 한 겹 추가하지 말고 package.json, netlify.toml, index.html이 기존 위치에 오도록 합니다.
  3. GitHub 웹에서는 Add file → Upload files에서 폴더 안 파일·폴더를 업로드하고 Commit changes를 누릅니다. GitHub Desktop을 쓰는 경우 저장소 폴더로 복사/덮어쓰기 → 변경 검토 → Commit → Push origin 순서입니다. 새로 추가된 server/auth.mjs, server/storage.mjs를 빠뜨리지 마세요.
  4. REMOVED_FILES.txt에 있는 옛 문서 정리 사항도 반영합니다. .env, API 키, 고객 JSON 백업, .netlify, 개인 SITE_ID.txt, node_modules는 GitHub에 올리지 않습니다.
  5. Commit 메시지는 v7.0.0 이메일 인증·신청오류·삭제복원 개선처럼 입력합니다.
  6. Netlify가 자동으로 검사와 빌드를 수행하는지 Deploys에서 확인합니다. Published/정식배포 완료 후 홈페이지에서 Ctrl+F5를 누릅니다.

B. 기존에 폴더 업로드만 했던 경우

GitHub에 비공개 저장소를 생성하고 v7 파일을 올린 후 기존 Netlify 프로젝트의 Project configuration → Build & deploy/Continuous deployment → Repository → Link repository(또는 Configure repository)에서 연결합니다. 새 프로젝트를 만드는 Add new project 흐름이 아닙니다. GitHub 계정에는 Netlify가 해당 저장소에 접근할 권한을 승인합니다. 화면 명칭은 계정·UI 버전에 따라 다를 수 있습니다.

dist 폴더나 index.html만 수동 업로드하면 안 됩니다. 인증번호, 비밀글, 데이터 저장은 서버 함수가 필요합니다. GitHub 연결 빌드에서 화면과 함수가 함께 배포되도록 합니다.

C. GitHub 연결 전에 긴급 업데이트가 필요한 경우

Node.js 22.12 이상이 있는 PC에서 v7 폴더의 01_LOGIN.cmd로 현재 프로젝트 소유 계정에 로그인하고 03_UPDATE_SITE.cmd를 실행합니다. 안내에 현재 homepage Project ID(UUID)를 입력하고, 대상 확인 후 UPDATE를 입력합니다. SITE_ID.txt는 안전을 위해 비워두었습니다. 이전 v3/v4 ID를 임의로 재사용하지 마세요. 이 방식은 임시 CLI 배포이며 GitHub 이력은 자동으로 기록되지 않으므로 나중에 같은 소스를 GitHub에도 저장합니다.

명령어에 --context를 별도로 추가하지 않습니다. 02_PREVIEW.cmd는 화면 시험용이지만 같은 프로젝트의 자료를 공유하므로 실제 고객자료를 삭제하거나 새 자료로 덮어쓰는 시험은 하지 마세요.

04 · 관리자 실제 사용

이메일 → 인증번호 → 관리자 화면

  1. 홈페이지 관리자 메뉴에서 v7.0.0 표시를 확인합니다.
  2. OPTIC_ADMIN_EMAIL에 저장한 이메일을 입력하고 이메일 인증번호 받기를 한 번 클릭합니다.
  3. 가장 최근 메일에 적힌 6자리 숫자를 입력합니다. 링크를 눌러 복구하는 방식이 아닙니다. 스팸함도 확인합니다.
  4. 정상 로그인 후 기본설정 → 개인정보 안내의 실제 담당자/보관기간/문의처 등을 검토하고 개인정보 안내 확인, 온라인 접수 허용을 저장합니다. 관리자가 인증되어야 접수가 열립니다.
  5. 가짜 연락처 등 테스트 자료로 검안상담·고객상담·예약주문 각각 1건을 작성합니다. 제목에 개인정보를 넣지 않습니다.
  6. 관리자 고객 글·답변에서 접수건을 확인하고 답변합니다. 비밀글 비밀번호가 없어도 관리자는 관리할 수 있습니다.

05 · 상담 신청과 등록 자료 삭제

무한 대기·중복 저장 방지와 휴지통

신청 버튼을 누르면 처리 중으로 바뀌고 중복 클릭을 막습니다. 서버응답이 20초 안에 끝나지 않으면 중단 안내와 함께 버튼을 복구하며 입력내용은 유지됩니다. 네트워크 요청을 무한 재시도하지 않습니다. 브라우저를 새로고침하지 말고 같은 작성화면에서 재시도하면 같은 신청번호로 중복 등록을 차단합니다. 새로고침/새 작성화면은 별도 신청이므로 먼저 공개 목록의 접수 여부를 확인하세요.

목록에는 고객의 제목·작성일·상태가 보입니다. 이름·전화번호는 공개하지 않습니다. 비밀번호를 설정한 글은 번호 검증 후 본문·답변을 볼 수 있고, 비밀번호 없는 글은 공개 동의한 본문만 공개됩니다. 민감한 시력·건강정보는 가급적 공개글에 넣지 말고 관리자 내부 기록으로 관리하세요.

06 · 운영자료는 GitHub가 아닌 서버에

Netlify Blobs 유지 + 하루 1회 자료 백업

GitHub는 코드·디자인 변경이력, Netlify Blobs는 고객·신청·제품·사진을 담당합니다. 코드만 업데이트하면 같은 Netlify 프로젝트와 같은 저장소의 기존 자료를 읽습니다. 코드 되돌리기와 고객자료 복원은 별개입니다.

자료 관리 기능v7 구현
정기 실행정식 배포에서 매일 한국시간 오전 04:17 (UTC 19:17)
자료 백업설정·등록자료·고객글·발송이력 JSON, 최근 7일 유지
정리만료 인증번호·로그인·요청제한 기록, 30일 지난 휴지통
운영 확인관리자 → 백업·가져오기에서 최근 백업 확인/내려받기 및 지금 백업
외부 보관월 1회 이상 관리자 JSON 내려받기 + 사진 원본을 별도 암호화 보관 권장
이 작업은 Supabase 정지 회피용 임의 쿼리가 아닙니다.
Netlify 요금제 한도·계정 정지·서비스 장애까지 방지하지는 못합니다. 예약 실행은 Production에서만 동작하고, Netlify 실행시간/용량 한도를 받습니다. 최근 백업이 갱신되는지 확인하세요.

백업은 같은 프로젝트 안의 사본이므로 프로젝트 전체 삭제에 대비한 외부 백업을 대신하지 않습니다. 여러 레코드를 읽은 논리 백업으로서 데이터베이스의 시점 일치 트랜잭션 백업과 같지 않습니다. JSON에는 업로드한 사진 바이너리·관리자 인증키가 포함되지 않습니다. 같은 프로젝트에서는 사진주소가 유지되지만 다른 프로젝트로 옮길 때는 사진을 별도 이관해야 합니다.

관리자 가져오기는 v3/v6/v7 JSON을 읽어 누락 자료를 추가하며 기존 같은 ID는 덮어쓰지 않습니다. 전체 롤백 도구가 아닙니다. 일부 오류 후 다시 가져와도 같은 자료를 반복 추가하지 않도록 했습니다. 설정 복원 선택 시 온라인 접수는 다시 꺼지므로 검토 후 켜세요. 삭제 표시가 있는 자료는 가져오기로 부활시키지 않습니다.

초기 대상은 한 매장의 소규모 자료입니다. 현재 안전한 요청크기 때문에 백업은 약 4.5MB, 업로드 이미지 요청은 약 3.2MB, 가져오기는 분류별 3,000건 등의 한도가 있습니다. 한도 초과는 명확한 오류로 멈춥니다. 다중 직원 동시 거래·재고 자동차감·대량 통계·회계 대사가 핵심이 되면 관계형 데이터베이스로 이전 검토가 필요합니다.

08 · 주소와 DNS는 그대로

도메인 연결과 향후 업데이트

v7로 바꾸기 위해 현재 도메인이나 Hosting.kr 네임서버를 변경할 필요는 없습니다. 같은 프로젝트에 배포하면 기존 Netlify 주소 및 연결된 도메인을 사용합니다. 요청하셨던 smartsamsunggopt.co.kr의 철자는 실제 보유 도메인과 비교하세요.

아직 홈페이지 도메인을 연결하지 않았다면 Netlify Domain management에서 도메인을 추가하고 표시된 연결정보를 현재 DNS 업체에서 적용합니다. 이 버전에서는 고정된 과거 IP 주소를 임의로 제시하지 않습니다. 이메일 인증용 하위도메인 DNS와 홈페이지 접속 DNS는 서로 다른 목적입니다. Resend의 안내 레코드만 추가하고 기존 MX/TXT를 지우지 않습니다.

앞으로 AI에 수정 요청 시 AI_UPDATE_REQUEST.txt와 현재 전체 소스를 첨부하고, 운영자료 JSON은 제외합니다. 수정본을 동일 GitHub 저장소에 반영 → Commit → Netlify 자동 검사/배포 → 버전 및 기능 확인 순서입니다. 기능 수정 후에도 기존 저장소 이름과 자료 형식을 유지하도록 요청하세요.

09 · 납품 확인 범위

검증 범위와 남은 실제 환경 확인

검사 결과는 docs/QA_REPORT.md와 docs/TEST_RESULTS.txt에 기록했습니다. 서버 단위/통합 모의 테스트와 PC·모바일 격리 브라우저 시험을 수행했습니다. 신청 중복 클릭, 네트워크 실패 후 복구, 비밀글 열람, 관리자 삭제·복원 등을 확인했습니다.

실제 계정에서 완료하지 않은 것: Netlify 배포·Blobs 실제 네트워크 저장·Resend 메일 전달·SOLAPI 문자/카톡 발송·GitHub 연결·DNS 변경은 사용자 계정에서 최종 확인해야 합니다. 자동 시험 통과가 무장애나 무제한 운영을 보장하지 않습니다.

기존 v6에서 실제 무한루프가 발생한 특정 요청의 운영 로그는 제공되지 않았습니다. 따라서 원인을 하나로 단정하지 않았으며, 요청시간 제한·중복호출·응답실패 복구를 보완하고 재현 시험을 수행했습니다.

운영 공개 전: 이메일 실수신 → OTP 로그인 → 기본설정 저장 → 사진 저장 → 검안·고객·예약 각 1건 → 비밀글 열람 → 관리자 답변 → 삭제·복원 → JSON백업 → 재배포 후 유지 → 다음날 예약 백업 시각 확인까지 점검하세요.
