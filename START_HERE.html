Resend 가입 · 이메일 인증번호 · Supabase SQL · 설정 확인코드가 필요하지 않습니다.
기존 홈페이지·사진·자료는 보존합니다.

해야 할 일은 세 가지입니다.

① 내 비밀번호 한 번 등록 → ② 같은 프로젝트에 업데이트 → ③ 그 비밀번호로 로그인

이전 홈페이지 프로젝트나 자료를 삭제하지 마세요. 현재 v7이 올라간 homepage 프로젝트를 그대로 사용합니다. 프로젝트 주소 이름보다 Project ID가 동일한지 확인하세요.

① 내가 사용할 비밀번호를 Netlify에 등록

Netlify 로그인 → 현재 homepage 프로젝트 → Environment variables → Add a variable로 이동하세요.

화면의 항목넣을 내용
KeyOPTIC_ADMIN_PASSWORD
Value대표님이 직접 정한 관리자 비밀번호
공백 없이 영문·숫자를 모두 포함한 12~128자. 외부에서 발급받는 키가 아닙니다.
Contains secret values체크
ScopesFunctions 포함. All scopes 선택도 가능
Deploy contextsSame value for all deploy contexts

저장하고, 비밀번호는 본인만 아는 곳에 보관합니다. 채팅·GitHub·index.html에 쓰지 마세요. 1111을 입력하지 않습니다. 기존 Resend/Supabase 키는 v7.1에서 사용하지 않으며 당장 삭제할 필요도 없습니다.

환경변수는 서버가 읽는 설정입니다. 이 비밀번호를 홈페이지 로그인에도 똑같이 입력합니다. 별도 설정코드는 없습니다.

② 기존 프로젝트를 v7.1로 업데이트

ZIP을 압축 해제하고 안쪽 폴더를 여세요. index.html, app.js, package.json, server, netlify 폴더가 함께 보입니다.

가장 쉬운 덮어쓰기: 현재 PC의 v7 작업 폴더를 먼저 백업한 후, v7.1 폴더 안의 파일과 폴더 전체를 기존 v7 작업 폴더에 복사·덮어씁니다. 원래 폴더의 SITE_ID.txt와 .netlify는 지우지 마세요. 이번 ZIP에는 SITE_ID.txt를 넣지 않아 기존 ID를 덮어쓰지 않습니다.

이미 사용하던 03_UPDATE_SITE.cmd를 실행하고 대상 프로젝트를 확인한 뒤 UPDATE를 입력합니다. 프로그램은 v7.1로 바뀌지만 현재 홈페이지 주소는 유지됩니다. v4/v5 폴더에서 실행하지 마세요.

기존 homepage의 Project ID가 없는 경우에만 한 번 입력을 요청합니다. 이전 v3/v4 ID를 임의로 입력하면 안 됩니다. 성공하면 Production deploy is live가 표시됩니다.

GitHub로 자동 업데이트하는 경우

같은 저장소의 기존 파일 위치에 v7.1 전체 내용을 반영하고 Commit/Push합니다. 바깥 폴더를 새로 추가하지 않습니다. server/auth.mjs와 server/core.mjs도 반드시 포함합니다.

Netlify 설정: Build npm run check && npm run build, Publish dist, Functions netlify/functions, Node 22. Netlify에서 Published 확인 후 홈페이지를 새로고침합니다.

.env, 비밀번호, 고객 JSON 백업, .netlify, SITE_ID.txt, node_modules는 GitHub에 올리지 않습니다.

index.html만 교체하거나 폴더 드래그만으로 배포하면 안 됩니다. 관리자 인증과 고객 접수는 서버 함수가 같이 배포되어야 합니다.

③ 관리자 로그인 → 접수 열기

현재 홈페이지에서 Ctrl+F5 → 관리자를 선택합니다. V7.1.0 / 비밀번호로 로그인이 보이면 ①에서 정한 비밀번호를 입력하세요.

로그인 후 대시보드의 온라인 접수 설정하기를 누릅니다. 실제 개인정보 안내를 확인·수정한 뒤 아래 두 항목을 체크하고 운영정보 저장을 누릅니다.

☑ 개인정보 안내를 검토·확정했습니다.
☑ 고객 상담·예약 접수를 받습니다.
[운영정보 저장]

고객 화면을 새로고침하면 접수버튼이 열립니다. 검안상담·고객상담·예약 각 1건을 시험하고, 관리자에서 답변 → 삭제 → 휴지통 복원까지 확인하세요. 실제 고객정보 대신 시험자료를 사용합니다.

이후 사진·공지·제품·상담 수정과 비밀번호 변경은 관리자 화면에서 합니다. 설정을 바꿀 때마다 Netlify에 다시 들어갈 필요는 없습니다.

비밀번호 변경과 분실

평소 변경: 관리자 → 비밀번호 변경 → 현재 비밀번호 → 새 비밀번호 두 번 → 저장. 다른 기기는 로그아웃됩니다. Netlify 재배포는 필요 없습니다.

잊었을 때만: Netlify의 OPTIC_ADMIN_PASSWORD를 이전에 쓰지 않은 새 비밀번호로 바꾸고 같은 프로젝트에 재배포한 다음 그 값으로 로그인합니다. 기존 자료는 유지됩니다. 이메일·문자·별도 확인코드는 없습니다.

관리자 화면에서 비밀번호를 바꾼 뒤에는 예전 초기 비밀번호가 다시 통하지 않습니다. 복구 시에는 새 값을 정해야 합니다. Netlify 계정 자체는 강한 비밀번호와 2단계 인증으로 보호하세요.

문제가 있으면 이것만 확인

화면 문구조치
V7.0.0 / 이메일로 로그인이전 배포입니다. 전체 소스와 함수를 재배포 후 Ctrl+F5.
ADMIN_PASSWORD_NOT_SET지금 접속한 프로젝트에 OPTIC_ADMIN_PASSWORD 등록. 12~128자 영문+숫자인지 확인하고 재배포.
PASSWORD_INCORRECT입력한 비밀번호 확인. 관리자 화면에서 변경했다면 변경 후 값을 입력.
온라인 접수 준비 중관리자 기본설정의 개인정보 안내 확인 + 접수 허용을 저장.
BLOBS_INIT / STORAGE_TIMEOUT새 프로젝트를 만들지 말고 연결 진단과 OP71- 오류번호 확인. 데이터를 초기화하지 않음.

비밀번호·인증키·고객자료 대신 오류번호와 화면만 공유하세요. 이 버전은 메일 발송서비스나 SQL을 요구하지 않습니다.

검증 범위와 자료 보존

Node.js 로컬 서버 테스트 84개, PC·모바일 격리 브라우저 점검 30개를 통과했습니다. 실제 20초 응답 지연과 중복 신청도 시험했습니다. 자세한 결과는 docs/QA_REPORT.md에 있습니다.

실제 사용자 계정의 Netlify 배포·Blobs 통신·Windows 명령 실행·유료 문자/카톡 발송은 이 환경에서 수행하지 않았습니다. 화면시험은 메모리 저장소와 로컬 Node 서버를 연결한 격리 환경입니다. 자동 시험이 실제 서비스 무장애를 보장하지는 않습니다.

기존 저장소 optic-v6-data, optic-v6-media 및 데이터 ID를 유지합니다. 새 프로젝트로 만들면 자동 이전되지 않습니다. 로그인 후 JSON을 내려받고 사진 원본도 별도 보관하세요. 백업은 코드 이전 버전 복원과 다릅니다. 같은 사이트의 시험 배포도 같은 자료를 공유합니다.
