스마트삼성구내안경원 · Supabase를 사용하지 않는 Netlify 전용 데이터 관리

먼저 확인하세요. 기존 Netlify 프로젝트와 Supabase를 삭제하지 마세요. v3의 자료를 먼저 백업한 뒤, 이 패키지를 깨끗한 GitHub 저장소에 올려 기존 smart-samsung-optic 프로젝트와 연결합니다. 앞으로의 새 데이터는 Netlify Blobs에 저장되며, 과거 Supabase 데이터가 자동으로 복사되는 것은 아닙니다.

Netlify Blobs는 객체 저장소이며 관계형 회계 DB가 아닙니다. 이 패키지는 소규모 단일 매장용으로 설계했습니다. 복잡한 동시 결제·여러 상품의 원자적 재고 차감·대용량 고객분석은 별도 설계가 필요합니다. 저장·조회·서버 실행량에 따라 요금이 달라지므로 Netlify 팀 요금제를 확인하세요.

원본 v3 사진·스타일 가져오기(필요한 경우)

원본과 동일한 사진을 사용하려면 PC에서 01_V3사진가져오기.cmd를 실행하고 보관한 Homepage.zip 또는 v3 폴더 경로를 입력하세요. 이 도구는 사진과 스타일만 복사하며 비밀번호·API 키·고객 자료는 가져오지 않습니다. 행사 JPG도 함께 선택할 수 있습니다. 가져온 뒤 v6 폴더를 GitHub에 올립니다. 사진은 설치 후 관리자에서도 교체할 수 있습니다.

2. GitHub에 프로그램을 보관합니다

  1. ZIP을 PC의 새 폴더에 압축 해제합니다. 폴더를 열었을 때 index.html, package.json, netlify.toml이 바로 보여야 합니다.
  2. 이전 v3 관리 화면에서 고객·제품 자료를 JSON으로 내보낼 수 있으면 먼저 개인 보관공간에 저장합니다. 해당 백업은 GitHub에 올리지 않습니다.
  3. GitHub에 대표자 계정으로 로그인하고 New repository를 누릅니다. 저장소명 예: smart-optic-website. 공개 범위는 Private을 권장합니다.
  4. 새 저장소에서 uploading an existing file 또는 Add file → Upload files를 선택합니다.
  5. 압축을 푼 폴더 안의 파일과 하위 폴더를 업로드합니다. 폴더를 한 겹 더 감싸서 올리지 마세요. assets, server, netlify, scripts, tests, .github도 포함합니다.
  6. Commit changes 설명을 v6.0.0 초기 설치로 기록하고 저장합니다. 저장소 첫 화면에 package.json이 보이는지 확인합니다.

3. 기존 Netlify 프로젝트와 연결합니다

지금 최종 주소로 사용할 프로젝트는 smart-samsung-optic입니다. 이전 시험 프로젝트 smart-samsung-optic-v4와 구분하세요. 서로 다른 프로젝트의 Netlify 저장소는 별개입니다. 과거에 알려주신 기존 프로젝트 ID는 fdcf0c88-83a1-420b-8ba8-29808503395c이지만, 실제 계정에서 이름과 ID를 다시 확인한 뒤 작업하세요.

3-1. 최초 설정 확인코드 하나를 등록합니다

  1. Netlify → Projects → smart-samsung-optic을 선택합니다.
  2. Environment variables → Add a variable로 이동합니다.
  3. Key는 OPTIC_SETUP_KEY, Value는 아래에서 생성한 긴 임의 문자열로 입력합니다. 20자 이상이어야 합니다.
  4. Contains secret values를 선택하고 Functions를 포함하는 범위에 적용합니다. All scopes를 선택해도 됩니다. 사용 중인 배포환경에 같은 값을 지정합니다.
  5. 생성한 값은 대표자 비밀번호 관리 도구에 별도 보관합니다. 이 안내 파일이나 GitHub에 쓰지 않습니다.

이 버튼은 이 브라우저에서만 난수를 생성합니다. 서버로 전송하거나 자동 저장하지 않습니다.

환경변수필수 여부설명

MESSAGING_ENABLED선택입력하지 않으면 실제 발송이 꺼져 있습니다. 처음은 false.
과거 SUPABASE_* / PUBLIC_SITE_URL사용 안 함v6는 읽지 않습니다. 다른 연결 프로그램에 사용하지 않는지 확인 후 정리할 수 있습니다. 먼저 제거할 필요는 없습니다.

3-2. 기존 사이트에 GitHub 저장소를 연결합니다

  1. 기존 Netlify 프로젝트의 Project configuration → Build & deploy → Continuous deployment → Repository에서 Link repository를 선택합니다. 화면에 따라 Developer settings 아래에 표시될 수 있습니다.
  2. GitHub 접근 승인을 진행하고 방금 만든 smart-optic-website 저장소를 선택합니다. 기존 연결이 있으면 Manage repository에서 변경 경로를 확인하세요.
  3. 아래 빌드 설정을 확인하고 저장합니다. 기본값은 패키지의 netlify.toml에 들어 있습니다.
  4. Deploys에서 GitHub 연결 빌드를 실행하거나 새 commit을 올려 배포를 시작합니다. 완료된 배포의 함수 목록에 optic, media, cleanup이 있는지 확인합니다.

index.html만 올리거나 폴더 드롭으로 화면만 배포하면 완료되지 않습니다. 고객 글·비밀번호·사진 저장에는 서버 함수가 필요합니다. 이번 안내의 기본 방식은 GitHub 연결 빌드입니다. 소스 폴더 전체를 정적 공개 폴더로 지정하면 안 됩니다. Publish directory는 반드시 dist로 둡니다.

Netlify의 사이트 단위 Blobs는 동일 프로젝트 내 재배포 후 유지되며, 같은 프로젝트의 시험 배포와 운영 배포가 저장소를 함께 쓸 수 있습니다. 시험 배포에서 실제 고객 자료를 지우거나 임의로 고치지 마세요. 완전히 분리된 테스트가 필요하면 별도 Netlify 프로젝트를 사용합니다.

4. 최초 관리자 로그인 → 비밀번호 변경 → 고객 접수 열기

  1. 배포된 홈페이지를 열고 관리자를 클릭합니다. 진단은 /#diagnostics에서 확인할 수 있습니다.
  2. 관리자 비밀번호에 1111, 최초 설정 확인코드에 방금 Netlify에 저장한 OPTIC_SETUP_KEY 값을 입력합니다.
  3. 첫 로그인 후 비밀번호 변경에서 현재1111 → 새 비밀번호12자 이상 → 확인을 입력합니다. 변경 전까지1111은 유지됩니다.
  4. 변경이 완료되면 새 비밀번호만으로 다시 로그인합니다. 설정 확인코드는 비워도 됩니다.
  5. 기본설정에서 상호·주소·전화번호·운영시간·휴무·개인정보 수집·보유 기간·삭제 요청 연락처를 실제 운영에 맞게 확정합니다.
  6. 개인정보 안내 검토 완료를 체크하고 고객 상담·예약 접수를 받습니다를 체크한 뒤 저장합니다.
초기 비밀번호1111이 공개된 상태에서 누군가 먼저 관리자 계정을 차지하지 못하도록 확인코드를 두었습니다. 실제 고객 접수와 개인자료 관리·발송은 비밀번호 변경 후 열립니다. 이것은1111을 자동 변경하는 것이 아니라 공개 초기 비밀번호 상태의 개인정보 사용을 제한하는 장치입니다.

6. Hosting.kr 도메인을 현재 홈페이지에 연결합니다

요청한 도메인은 정확히 smartsamsunggopt.co.kr입니다. samsung 다음에 gopt가 이어지는 철자입니다. Hosting.kr에서 실제로 소유한 도메인이 이 철자인지 먼저 확인하세요. 이 안내는 도메인 연결 방법이며, 현재 DNS를 자동으로 바꾸지 않습니다.

6-1. Netlify에 도메인을 먼저 등록

  1. Netlify → smart-samsung-optic → Domain management로 들어갑니다.
  2. Add a domain 또는 Add custom domain에서 smartsamsunggopt.co.kr를 추가합니다.
  3. www.smartsamsunggopt.co.kr도 등록되어 있는지 확인하고 없으면 추가합니다.
  4. Netlify가 제시하는 외부DNS 설정값을 확인합니다. 전용 Edge 등 특수 구성은 표시되는 값이 아래 일반 예시와 다를 수 있으므로 계정 화면의 안내값을 우선합니다.

6-2. Hosting.kr에서 현재 DNS 관리 위치 확인

  1. Hosting.kr에 로그인 → 나의서비스/도메인 관리 → 도메인 선택 → 네임서버/DNS 관리로 이동합니다.
  2. 해당 도메인의 실제 권한 네임서버가 Hosting.kr인지 확인합니다. 네임서버가 다른 업체라면 그 업체에서DNS를 수정해야 합니다.
  3. 기존 DNS 레코드를 캡처해 보관합니다. 이메일용 MX·TXT·SPF·DKIM·DMARC는 삭제하지 않습니다.
  4. 현재 웹사이트를 가리키는 같은 이름의 A/AAAA/CNAME 충돌 여부를 확인합니다. 기존 웹사이트를 교체하는 경우에만 해당 웹 레코드를 변경합니다. 관계없는 레코드는 그대로 둡니다.

6-3. DNS 레코드 입력 예시

방식유형호스트/이름값/대상
www 연결CNAMEwwwsmart-samsung-optic.netlify.app
루트 도메인 권장: Alias 지원 시ALIAS 또는 CNAME(Alias)@ 또는 빈칸apex-loadbalancer.netlify.com
루트 도메인 대안: Alias 미지원 시A@ 또는 빈칸75.2.60.5
루트는 두 방법 중 하나만 선택합니다. Alias와A를 같은 호스트에 중복 입력하지 않습니다. 일반 CNAME을 루트에 무조건 넣는 방식은 피하세요. Hosting.kr의 CNAME(Alias)는 지원되는 클라우드 네임서버에서 사용할 수 있으므로, 해당 메뉴가 없으면A대안을 검토합니다. 이를 위해 기존 이메일 설정을 확인하지 않고 네임서버부터 변경하지 마세요.

DNS 대상값에는 https://, /, #home을 붙이지 않습니다. 예를 들어www의CNAME 값은 smart-samsung-optic.netlify.app만 입력합니다. TTL은 서비스 기본값으로 시작해도 됩니다.

6-4. 적용·HTTPS·대표 주소 확인

  1. Hosting.kr에서 저장한 뒤 Netlify의 도메인 화면으로 돌아갑니다. DNS 전파에는 시간이 걸릴 수 있습니다. 즉시 안 된다고 레코드를 반복 교체하지 마세요.
  2. Netlify의 DNS/HTTPS 확인을 진행하고 인증서가 두 도메인을 포함하는지 확인합니다. HTTPS에 문제가 있으면 기존 CAA 레코드와DNS 충돌 여부를 점검합니다.
  3. 외부DNS를 사용할 때는 www.smartsamsunggopt.co.kr를 기본주소(Primary domain)로 두고, 루트 도메인이www로 이동하는 구성을 권장합니다.
  4. 브라우저에서 루트와www 두 주소를 각각 열고, 보안 경고 없이 접속되는지 확인합니다.
  5. 새 도메인에서 관리자에 다시 로그인하고 사진·비밀글을 시험합니다. 같은 Netlify 프로젝트라면 데이터는 같지만 도메인이 달라 로그인 쿠키는 다시 필요합니다.
최종 확인 주소
https://smartsamsunggopt.co.kr
https://www.smartsamsunggopt.co.kr

기존 주소도 같은 프로젝트를 가리킵니다.
https://smart-samsung-optic.netlify.app

도메인 연결을 위해 별도 Hosting.kr 웹호스팅을 추가 구입할 필요는 없습니다. 실제 호스팅은 Netlify를 사용합니다. 도메인 갱신 비용과 Netlify 이용요금은 각각 관리하세요. v6는 같은 사이트 기준으로 요청을 처리하므로 Supabase Redirect URL이나PUBLIC_SITE_URL을 다시 등록하지 않습니다.

7. 앞으로AI 수정 ZIP을 받아 쉽게 업데이트하는 방법

내용만 바꿀 때: 파일 업로드 없이 관리자에서 저장

사진, 행사, 팝업, 운영시간, 제품정보, 고객답변은 홈페이지 관리자 메뉴에서 바꿉니다. GitHub/Netlify를 매번 만질 필요가 없습니다.

프로그램 기능이나 디자인을 바꿀 때

  1. 수정 요청 시 현재 버전과 현재 GitHub 소스 ZIP을AI에 제공합니다. 고객 백업·비밀키는 제외합니다. AI_UPDATE_REQUEST.txt 예문을 사용하세요.
  2. 새 ZIP을 별도 폴더에 풉니다. 기존 버전 ZIP도 날짜별로 보관합니다.
  3. 현재 관리자에서 고객 데이터를 JSON으로 백업합니다. 원본 사진은 별도 보관합니다.
  4. GitHub의 같은 저장소에서 Add file → Upload files로 변경 파일을 같은 경로에 덮어씁니다. 전체 새 패키지 업로드도 가능하지만 REMOVED_FILES.txt의 삭제 대상 파일은 따로 확인합니다.
  5. Commit 설명에 v6.0.1 - 행사 팝업 개선처럼 버전·내용을 적습니다.
  6. Netlify가 자동 빌드 후배포합니다. 새 프로젝트를 만들지 않습니다. Deploys에서 성공 여부를 확인합니다.
  7. 홈·관리자·고객글·사진 저장을 테스트하고 릴리스 메모를 남깁니다.
GitHub Desktop 이용 시
저장소를PC로 Clone → 변경 전 Pull → .git 폴더는 유지하고 새 패키지 파일 덮어쓰기 → Changes에서 확인 → Commit → Push 순서입니다. 고객 백업JSON, .env, .netlify, node_modules는 넣지 않습니다.

GitHub Commit/Release는 프로그램 버전의 이력입니다. Netlify의 이전 배포로 되돌려도 고객 데이터·사진 변경이 함께 되돌아가지는 않습니다. 특히v3와v6는 데이터 저장방식이 달라 코드만v3로 되돌린다고v6자료를 읽을 수 있는 것은 아닙니다.

8. 데이터 백업·이전·대표자 인계

자료보관·이전 방법
v3 JSON 자료v3 내보내기 후v6 관리자 → 백업·가져오기. 제품·재고·고객 자료는 추가 가져오기. 비밀번호 없는 옛 상담/예약/발송은 관리자 전용 기존자료 메뉴로 이동합니다.
Supabase에만 있는 데이터이 패키지가 자동 가져오지 않습니다. 기존 시스템 내보내기 또는 별도 변환 후 검토하여 가져오세요. 완료 전 Supabase를 삭제하지 마세요.
v6 JSON 백업설정·관리 레코드·게시글·발송이력을 저장합니다. 고객 본문 및 비밀번호 해시를 포함하므로 민감한 개인 보관자료입니다. 세션과 관리자 비밀번호는 제외합니다.
사진 원본JSON에는 사진주소만 포함됩니다. 원본 파일은 별도로 저장하세요. 다른 프로젝트로 이전할 때 다시 업로드해야 할 수 있습니다.
복원 범위현재 가져오기는 추가형 레코드·비밀글 복원입니다. 설정·사진 파일·모든 발송이력의 일괄 완전복구는 자동 제공하지 않습니다. 실제 재해복구는 보관자료와 함께 별도 점검합니다.

대표자에게 인계할 항목: GitHub·Netlify·Hosting.kr 계정 소유권, 관리자 새 비밀번호, 설정 확인코드, 도메인 갱신일, 운영시간·개인정보 안내,백업 위치, 선택한 문자업체 계정과 비용관리 방법. 플랫폼 계정은2단계인증을 설정하고, PM은 필요한 권한만 공유받는 방식이 적절합니다.

9. 관리자 비밀번호를 잊었을 때

  1. Netlify 프로젝트 소유자 계정으로 로그인합니다.
  2. Environment variables에 OPTIC_RESET_VERSION을 추가하고 이전에 사용하지 않은 값(예: 20261017-reset-1)을 입력합니다. 이 값은복구 요청회차 표시이지 비밀번호가 아닙니다.
  3. 프로젝트를 새로 배포합니다. 고객 데이터는 삭제하지 않습니다.
  4. 홈페이지 /#owner-reset에서 설정 확인코드와 새 비밀번호를 입력합니다.
  5. 성공하면 기존 로그인 세션은 만료되고 새 비밀번호를 사용합니다. 같은복구버전은 재사용할 수 없습니다.

설정 확인코드도 잊었다면Netlify 소유자 권한으로 OPTIC_SETUP_KEY를 새 난수로 변경하고 새복구버전과 함께 재배포합니다. 이메일복구 링크·localhost·Supabase 비밀번호는 사용하지 않습니다. Netlify 소유자 계정 자체를 잃은 경우에는 해당플랫폼 계정복구가 먼저 필요합니다.

10. 문자·카톡 발송과 이력

처음에는 테스트 모드로 수신자·내용·결과를 기록합니다. 고객에게 보내지 않습니다. 수동 발송 기록은 별도휴대전화나업체화면에서 보낸 사실을 관리자가 기록하는 기능이며, 시스템이 전달완료를 보증하지 않습니다.

상태의미
TEST실제 발송 없음
MANUAL_UNVERIFIED수동 기록·전달 여부 미검증
ACCEPTED발송업체가 요청을접수, 고객에게도착한뜻아님
DELIVERED업체 결과조회에서 전달완료 확인
FAILED / UNKNOWN실패 또는 접수 여부불명확. UNKNOWN이면 중복발송하지 말고업체 내역확인

실제 발송을 사용할 경우SOLAPI계정·등록 발신번호·잔액·API 키를 준비하고 Netlify환경변수에 SOLAPI_API_KEY, SOLAPI_API_SECRET, SOLAPI_SENDER를 등록합니다. MESSAGING_ENABLED=true로 바꾸고재배포합니다. 카카오알림톡은승인된 채널PFID(SOLAPI_KAKAO_PFID)와템플릿ID/변수가 추가로필요합니다. 키를 홈페이지 입력칸이나GitHub에 넣지않습니다.

이 패키지는 특정 외부API로만 발송하며 사용자가입력한 임의의URL로 비밀키를 전달하지 않습니다. 예약확인·제품수령 등정보성 안내를 대상으로 합니다. 광고성 메시지발송은 별도 동의·표시·수신거부·업체 정책을 검토해야하며본프로그램이법적충족을보증하지않습니다. 실제업체승인·과금·발송시험은대표자계정에서필요합니다.
